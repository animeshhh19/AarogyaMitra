Objective for the Week

The objective of Week 1 was to understand the frontend and user-experience requirements of the platform, research an existing open-source reference implementation, and contribute the portal and UI-related sections to the project proposal.

Day 1 — Problem Understanding

Analysed the user-facing pain points described in the problem statement, for example patients not being able to easily see doctor availability or track the status of a booked consultation.

Looked at what the patient portal and doctor dashboard would each need to expose, for example registration, profile management, and appointment status, so both sides have a clear view of the consultation lifecycle.

Day 2 — Existing Systems and Research

Studied the reference open-source implementation's frontend, for example its use of Next.js with a component library for the patient and doctor portals.

Reviewed how the existing project structures its pages and components, to understand which parts could be reused or adapted for our own portal.

Day 3 — Portal Structure Planning

Sketched the page structure for the patient portal, for example registration and login, profile management, doctor discovery, and appointment booking.

Sketched the page structure for the doctor dashboard, for example availability management, appointment queue, and consultation history.

Day 4 — UI and Component Planning

Researched the Shadcn component library and how it pairs with Next.js, to plan a consistent look across the patient and doctor sides of the platform.

Noted the operational constraint from the proposal that the solution needs to stay usable on low-to-mid range devices, and planned to keep the component choices lightweight with that in mind.

Day 5 — Consultation UI Planning

Planned how the consultation UI, for example the chat and video call screens, would need to fit into the same portal without feeling like a separate app.

Coordinated with the teammate handling the real-time layer to understand what UI hooks the chat and video components would need, for example connection status and room join state.

Day 6 — Proposal Finalisation

Finalised my sections of the proposal with the team, covering the patient portal, doctor dashboard, and the overall frontend approach using Next.js and Shadcn.

Reviewed the proposal for consistency between the frontend section and the backend and real-time sections, for example making sure the portal pages matched the API endpoints being planned.

Week 1 Deliverables

Studied a working reference implementation's frontend structure and component approach.

Sketched the page structure for the patient portal and doctor dashboard.

Planned the UI component approach using Next.js and Shadcn, with low-to-mid range device usability in mind.

Planned how the consultation UI would integrate with the real-time layer.

Contributed my sections to the finalised project proposal.

Individual Contribution

My primary contribution this week was on Part 1 — the frontend and patient/doctor portal design. I researched the reference implementation's frontend structure, sketched the page layouts for both portals, planned the component approach, and coordinated with the real-time layer teammate on how the consultation UI would fit together.
